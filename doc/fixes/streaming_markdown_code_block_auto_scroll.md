# 流式 Markdown 代码块自动滚动中断

## 验收结论

本问题已完成复现、修复和自动化验证，并于 2026-08-07 通过用户本地实测验收。修复后，流式生成普通文本和代码块时，视口与滚动条都能持续跟随最新内容；后续又收紧了用户主动上滚的判定，确保阅读历史或当前回答已渲染部分时立即暂停自动跟随，同时继续接收和渲染流式输出。

> 2026-08-08 后续演进：主对话滚动又增加了对“内容收缩导致浏览器钳制滚动位置”的识别，避免思考面板自动折叠被误判为用户上滚。详见 [思考面板折叠后最终回答自动滚动中断](reasoning_panel_collapse_auto_scroll.md)。

## 问题现象

AI 流式输出普通文本时，对话区域通常会持续向下滚动。当输出进入 Markdown 代码块后，自动滚动有概率突然停止，视口和滚动条都停留在旧位置。后续内容仍在生成，但只能依靠用户手动滚动才能看到。

问题只在部分时序下出现，代码块越长、单次布局高度变化越大，越容易触发。

## 根因

问题来自消息数据更新、Markdown DOM 更新和滚动状态判断之间的竞态：

1. [`App.vue`](../../apps/web/src/App.vue) 监听消息正文变化，并在 Vue 的下一次 DOM 更新后滚动到底部。
2. [`MarkdownContent.vue`](../../apps/web/src/components/MarkdownContent.vue) 为降低重复解析和代码高亮开销，以约 33ms 的间隔节流 Markdown 渲染。
3. 因此，父组件的滚动可能先发生，而代码块 DOM 会在稍后才被替换和增高。父组件滚动时读取到的 `scrollHeight` 仍是旧值。
4. 滚动容器原本设置了 `scroll-behavior: smooth`。程序化滚动与代码块布局增长交错时，中间产生的 `scroll` 事件可能距离新底部超过 96px。
5. 原滚动处理逻辑把“当前不在底部”直接解释为“用户主动上滚”，于是关闭自动跟随。后续消息更新看到跟随状态已关闭，便不再尝试滚动。

代码块需要反复解析、高亮并整体替换 DOM，而且高度经常一次增长多行，因此比普通文本更容易放大这一时序窗口。

## 修复方案

### 根据实际布局变化跟随

在 [`App.vue`](../../apps/web/src/App.vue) 中使用 `ResizeObserver` 观察对话内容容器。Markdown 或代码块真正完成 DOM 更新并改变布局高度后，只要用户仍处于跟随状态，就立即按最新 `scrollHeight` 贴到底部。组件卸载时会断开 observer。

### 区分内容增长与用户上滚

滚动处理最初记录前后两次 `scrollTop`，后续又加入最大滚动位置和底部距离：

- 用户操作使滚动位置向上且底部距离增加时，立即暂停自动跟随；该判断优先于 96px 底部恢复阈值，因此小幅上滚也不会被拉回。
- 如果最大滚动位置随内容收缩而减小，且视口到底部的距离没有增加，则把 `scrollTop` 的同步减小视为布局调整并继续跟随。
- 未识别到用户上滚且距离底部小于 96px 时，保持或恢复自动跟随。
- 内容增高导致底部距离变大、程序化滚动及内容收缩造成的浏览器布局调整，不再被误判为用户操作。
- 暂停自动跟随只改变前端视口状态，不调用停止生成或取消请求；当前流继续接收、排空并完成持久化。

这保留了原有交互：用户可以主动上滚阅读上一条回答或当前回答已经渲染的部分，向下回到接近底部的位置后自动恢复跟随，也可以点击“回到底部”显式恢复。

### 流式跟随使用即时滚动

流式跟随通过直接设置 `scrollTop` 即时贴底，并从 [`style.css`](../../apps/web/src/style.css) 移除了滚动容器默认的 CSS 平滑滚动。用户点击“回到底部”时仍会显式使用平滑滚动。

## 回归测试

[`fixture_server.ts`](../../e2e/fixture_server.ts) 提供包含 80 行 TypeScript 代码的流式响应场景；[`chat.spec.ts`](../../e2e/chat.spec.ts) 使用 900×500 视口覆盖两条互补路径。

自动跟随路径检查代码块生成结束后：

```text
scrollHeight - scrollTop - clientHeight <= 1px
```

同一用例在修复前稳定失败，视口距离底部为 1261px；修复后距离不超过 1px，并稳定通过。

用户阅读路径使用专用的较慢分片，在“停止生成”按钮仍可见且结束文本尚未出现时向上滚动 48px。这个距离刻意小于 96px 底部阈值，用于验证向上滚动拥有更高优先级。测试随后检查：

- “回到底部”按钮立即出现。
- 流式代码块继续增长并最终出现结束文本。
- 回答没有进入 `stopped` 状态，生成结束后“停止生成”按钮消失。
- 视口与底部的距离增长到 96px 以上，证明新内容没有强制把用户拉回底部。

## 最终效果

- 普通文本和 Markdown 代码块在流式生成期间持续贴住最新输出。
- 代码块解析、高亮或整体 DOM 替换不会再关闭自动跟随。
- 用户主动向上滚动时立即暂停跟随，不论阅读的是历史回答还是当前回答已渲染的部分，也不论是否仍在 96px 底部阈值内。
- 暂停跟随不会停止、取消或截断正在进行的流式输出。
- 视口内容与滚动条位置保持同步。
