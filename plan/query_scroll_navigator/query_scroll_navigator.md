# 正文区域用户 Query 定位滚动条

## 目标

在聊天正文区域左侧增加一组仿 ChatGPT 的用户 Query 定位横杠，帮助用户在长对话中快速识别当前所处轮次，并跳转到任意历史用户问题。

定位器同时提供紧凑预览：用户 Query 单行显示并使用白色高亮，关联的 assistant 正文使用灰色显示并最多保留三行。定位器视窗最多展示五条横杠；会话超过五个 Query 时，用户可在定位器上使用滚轮浏览其余条目。

本功能只增强 Web 端的长对话导航，不修改聊天消息、SSE、会话持久化或模型上下文契约。

## 当前基线

- `VirtualMessageList.vue` 使用 `@tanstack/vue-virtual` 渲染动态高度消息，并独占 `.conversation-scroll` 的滚动状态、行测量和自动跟随逻辑。
- 每条 `RenderedChatMessage` 都有页面生命周期内稳定的 `renderKey`，并保留 `turnId`、`position`、`role`、`content` 和状态。
- 同一轮的 user 与 assistant 消息共享 `turnId`，可以在前端可靠配对；乐观消息在服务端 `meta` 到达前也已共享本地 turn ID。
- 虚拟列表只挂载视口和 overscan 范围内的消息，不能依赖查询全部用户消息对应的 DOM 节点来建立导航。
- `VirtualMessageList` 当前只对 `App.vue` 暴露 `scrollToBottom()`，尚未暴露按消息索引定位的能力。
- 主正文列最大宽度为 860px，滚动容器隐藏横向溢出；860px 和 680px 已存在响应式断点。

## 已确认范围

- 一个导航条目对应一条 user 消息，而不是每一条消息。
- 使用相同 `turnId` 的 assistant 最终正文作为该 Query 的摘要来源。
- Query 预览固定为一行，超出宽度时显示省略号。
- 正文预览固定为最多三行，使用灰色弱化显示，且不包含思考过程。
- 定位器同一时间最多渲染五条可见横杠。
- Query 数量超过五条时，定位器区域接管纵向滚轮以浏览前后条目。
- 当前正文轮次使用白色、较长横杠；非当前项使用灰色、较短横杠。
- 横杠支持点击定位到对应 user 消息；正文滚动时同步当前高亮项。
- 保持现有虚拟列表、流式自动跟随、回到底部、思考面板和会话切换行为。
- 首期只在具有足够横向空间的桌面布局展示；窄屏隐藏定位器，避免遮挡正文和输入区。

## 交互规格

### 导航条目与预览

- 导航项按消息 `position` 升序排列，稳定键使用 user 消息的 `renderKey`。
- 鼠标悬停横杠或键盘聚焦按钮时，在横杠右侧显示预览卡片。
- 卡片第一行展示规范化后的用户 Query：白色或主题中的高对比文本、单行、省略号截断。
- 卡片正文展示同一 `turnId` assistant 的 `content`：灰色、最多三条视觉行、超出截断。
- 正文预览使用普通文本渲染，不使用 `v-html`；折叠 Markdown 标记和连续空白，避免把标题符号、代码围栏或换行直接带入卡片。
- `reasoningContent` 不进入预览，避免泄露折叠状态之外的思考内容，也避免摘要长度随思考流增长。
- assistant 尚未返回正文时，根据消息状态显示“正在生成回答…”、“回答已停止”或“暂无回答”等灰色占位文本。
- 卡片只承担预览，不形成第二个可滚动正文区域；离开悬停、失去焦点或按 Escape 后关闭。

### 居中五槽滑动窗口

- 定位器改为“固定五槽视窗 + 上下各一条缓冲横杠”的滑动窗口，而不是每次直接替换五条 DOM。
- 当前 Query 始终映射到物理上的中间（第三）槽位；白色、较长的高亮横杠固定在该槽位，数据项在其下方经过。
- 例如共有 9 条 Query、当前为第 5 条时，五个完整槽位依次显示第 3、4、5、6、7 条，中央高亮代表第 5 条。
- 在定位器内向上滚动时，横杠轨道向下连续位移：第 2 条从第一条上方逐渐露出，第 7 条从底部退出；完成一个步进后稳定为第 2、3、4、5、6 条，中央高亮代表第 4 条。
- 在定位器内向下滚动时，横杠轨道向上连续位移：第 8 条从第五条下方逐渐露出，第 3 条从顶部退出；完成一个步进后稳定为第 4、5、6、7、8 条，中央高亮代表第 6 条。
- 触控板的小幅连续 `deltaY` 直接驱动露出比例；鼠标滚轮单格则播放一次等价的短滑入动画。一个阈值只跨越一个 Query，快速连续滚动可按顺序衔接多个步进。
- 正文滚动导致当前 Query 变化时复用同一居中规则；大跨度跳转可直接居中目标项，避免排队播放过长的中间动画。
- 保持当前语义：定位器滚轮仅浏览并更新预览/浏览游标，点击、Enter 或 Space 才跳转正文；鼠标悬停、焦点和预览交互不变。
- 首尾不伪造横杠：第 1 条或最后一条仍处于中间高亮位，缺少 Query 的侧边保留为空，以直观表示对应方向已无更多内容。
- 静止时只显示五条完整横杠（首尾附近可因真实条目不足而更少）；第六条仅在滚动过渡时从上/下边缘部分显现。

### 当前项同步

- 当前项表示正文阅读锚点所属的最近一个 user Query，而不是“当前悬停项”。
- 在滚动容器顶部增加一个小的激活偏移，取进入该阅读锚点的第一条实际可见消息索引。
- 从 Query 索引中选择不大于该消息索引的最后一个 user 条目；处于首轮之前时选择第一项，抵达底部时选择最后一项。
- 计算实际可见项时排除 virtualizer 的纯 overscan 行，不能直接把 `virtualItems[0]` 当作当前阅读位置。
- 正文滚动、虚拟行重新测量、窗口尺寸变化和会话切换后均重新同步当前项。
- 悬停或键盘聚焦只改变预览目标，不改变当前项；点击跳转完成后才由正文位置更新高亮。

### 点击定位

- 点击横杠后调用同一个 virtualizer 的索引滚动能力，以 user 消息的数组索引作为目标并按顶部对齐。
- 跳转到历史 Query 前关闭 `followOutput`，防止正在生成的尾部消息立即把视口拉回底部。
- 动态高度消息首次定位可能基于估算值；在下一帧和目标行测量后进行一次有限校正，确保 user 消息落在预期阅读锚点附近。
- 不对动态高度未测量列表强制使用长距离平滑滚动；优先保证定位准确，并遵守 `prefers-reduced-motion`。
- 跳转不改变当前会话、消息内容、思考面板展开状态或生成状态。

## 技术方案

### Query 数据投影

新增纯函数从 `RenderedChatMessage[]` 构建轻量导航元数据：

```ts
interface QueryNavigationItem {
  key: string;
  turnId: string;
  messageIndex: number;
  userMessage: RenderedChatMessage;
  assistantMessage: RenderedChatMessage | null;
}
```

构建过程单次扫描消息数组：

1. 按 `turnId` 记录 assistant 消息引用。
2. 为每条 user 消息生成导航项并保存原数组索引。
3. 使用 `turnId` 关联 assistant；缺失或异常顺序不会导致条目消失。
4. 会话切换或消息数量、身份结构变化时重建索引。

导航元数据只保存消息对象引用，不在结构计算中复制全部历史正文。五项视窗和当前预览按需读取对应 `content`，避免流式输出每个字符都扫描、拼接整段会话历史，保持长对话虚拟列表优化的性能边界。

### 组件边界

新增 `QueryScrollNavigator.vue`，负责：

- 居中五槽视窗、上下缓冲项、滚轮累计和边界。
- 横杠按钮、当前态、悬停态和焦点态。
- 单行 Query 与三行正文预览卡片。
- 点击、Enter、Space、Escape 和无障碍属性。
- 向父组件发出目标 `messageIndex`，不直接操作正文 DOM。

新增 `query_scroll_navigator.ts`，承载可独立测试的纯逻辑：

- user/assistant 按 turn 配对。
- Query 和 Markdown 正文的普通文本预览规范化。
- 居中五槽视窗、缓冲渲染范围和当前项可见计算。
- 根据实际可见消息索引选择当前 Query。
- 滚轮方向及累计阈值计算。

`VirtualMessageList.vue` 继续拥有唯一的正文滚动控制权，负责：

- 向定位组件提供导航项和当前项。
- 将定位请求转换为 `virtualizer.scrollToIndex()`。
- 在现有 `handleScroll()` 中同步可见消息索引和 `followOutput`。
- 在动态测量后执行必要的定位校正。
- 在会话切换时重置定位器窗口、悬停目标和滚轮累计。

`App.vue` 不建立第二套消息滚动监听；除非组件根结构调整影响布局，否则只维持现有 `VirtualMessageList` 接口。

### 布局与样式

- 为虚拟列表增加不滚动的相对定位宿主，正文滚动容器与定位器作为同级元素；定位器绝对定位在正文列左侧。
- 正文仍由 `.conversation-scroll` 独立滚动，定位器不随消息内容上下移动。
- 横杠使用统一按钮命中区包裹细视觉线，保证鼠标和键盘操作面积不受线条厚度限制。
- 当前横杠采用高对比白色/主题前景色并加长；普通横杠使用弱对比灰色，hover/focus 提高对比度。
- 预览卡片位于横杠右侧，采用与当前主题一致的浮层背景、圆角、边框和阴影，宽度受视口限制。
- Query 使用单行 ellipsis；正文使用三行 `line-clamp`，同时保留无 clamp 环境下的最大高度和溢出隐藏兜底。
- 定位器层级高于正文消息、低于会话抽屉、模态框、错误提示和输入区。
- 在现有桌面宽度下不得压缩 860px 正文列；空间不足时隐藏定位器，不改变正文宽度或产生横向滚动。
- 深色与浅色主题均复用现有 CSS 变量，不写死只能在深色主题使用的颜色。
- 横杠轨道放入固定高度、裁切溢出的五槽视窗；渲染范围包含上下缓冲项，并以 `translateY` 表达手势进度。中央高亮使用独立覆盖层且不拦截横杠按钮命中。
- 为 `prefers-reduced-motion` 提供无连续过渡的离散步进兜底，同时保留正确的居中窗口和边界状态。

### 虚拟列表与滚动状态

- 不查询离屏 DOM，不为全部 Query 创建隐藏锚点；定位目标始终是消息数组索引。
- 当前项计算复用 virtualizer 的尺寸和虚拟行范围，同时基于 `scrollTop` 排除 overscan。
- 新增按索引定位方法时保留现有 `scrollToBottom()` 语义，不让定位器直接写入 `scrollElement.scrollTop` 和 virtualizer 两套状态。
- 程序化跳转需要显式更新滚动基线，避免下一次 `handleScroll()` 把高度校正误判为用户操作。
- 跳到历史位置时暂停尾部跟随；跳到最后一轮也不直接假设已到底部，仍由现有 96px 阈值决定是否恢复跟随。
- 流式尾部增长只更新相关预览和总尺寸；用户正在浏览历史 Query 时不能改变其阅读位置。
- 会话切换、清空会话和新建会话后销毁旧导航状态；0 条 user 消息时完全不渲染定位器。

### 无障碍与键盘操作

- 每条横杠使用原生 `button`，可通过 Tab 聚焦，并支持 Enter、Space 跳转。
- 定位器提供描述性 `aria-label`，包括 Query 序号和规范化后的问题文本。
- 当前项使用 `aria-current="location"`；预览卡片通过 `aria-describedby` 与聚焦按钮关联。
- 预览出现不能抢走焦点，也不能作为 `aria-live` 内容反复播报。
- Escape 关闭预览并保留横杠焦点。
- 视觉线条之外保留足够命中区域和明确 focus-visible 样式。
- `prefers-reduced-motion` 下禁用非必要过渡和滚动动画。

## 数据与 API 边界

本功能不修改：

- `ChatMessage`、`ChatResponse`、SSE 事件或共享 Zod Schema。
- SQLite Schema、Repository、会话 API 和消息顺序规则。
- DeepSeek Provider、模型上下文或推理内容持久化。
- 会话列表与自动标题逻辑。

所有 Query 导航数据均由已加载到浏览器的当前会话消息派生，不产生额外网络请求，也不写入 localStorage。

## 实现顺序

1. 为 Query 投影、turn 配对、预览规范化、当前项和居中五槽窗口建立纯函数及测试。
2. 将五项窗口改为带上下缓冲项的居中滑动轨道，实现固定中央高亮、连续位移、鼠标滚轮过渡和首尾留空。
3. 调整 `VirtualMessageList` 根布局，在不改变正文滚动容器的前提下挂载定位器。
4. 基于真实可见索引同步当前 Query，并处理 overscan、顶部、底部和动态测量。
5. 接入 `scrollToIndex`、历史跳转暂停跟随和测量后的有限校正。
6. 完成主题、层级、断点、三行截断、focus-visible 和 reduced-motion 样式。
7. 补齐组件及 Playwright 测试，回归流式跟随、回到底部、会话切换和虚拟 DOM 上限。
8. 运行完整验证；用户验收后将计划标记为 `accepted` 并归档 `doc/` 最终文档。

## 测试计划

### 纯逻辑与组件

- 0、1、5、6 和大量 Query 时窗口数量、起点和边界正确。
- user 与 assistant 按 `turnId` 配对，不依赖相邻数组位置。
- 缺少 assistant、流式空正文、停止和错误状态返回正确占位摘要。
- Query 连续空白和换行折叠为单行；Markdown 正文转换为安全普通文本。
- 正文卡片最多三行，Query 单行省略，超长中英文、Emoji 和代码内容不撑破卡片。
- 滚轮小增量正确累计，一次阈值只移动一项，首尾不越界。
- 9 条 Query 且当前为第 5 条时，完整可见项为第 3 至第 7 条，中央高亮为第 5 条。
- 向上/向下滚动过程中，上/下缓冲项分别从边缘渐显；步进稳定后窗口分别变为 2–6 / 4–8，中央高亮始终处于第三槽位。
- 首条和末条保持中央高亮，缺失方向不渲染伪横杠；`prefers-reduced-motion` 下也维持正确的最终映射。
- 当前项变化时窗口自动包含该项；用户手动浏览时可查看当前窗口之外的历史项。
- hover、focus、Escape、Enter 和 Space 行为符合交互规格。
- 当前项与预览项状态相互独立，`aria-current` 和描述关系正确。

### 虚拟列表与滚动

- 当前阅读 user 消息时高亮该 Query，继续阅读其 assistant 正文时保持同一 Query。
- 滚过下一条 user 消息的激活锚点后只切换一次当前项。
- overscan 中尚未实际进入视口的 user 行不会提前高亮。
- 点击首项、中间项和末项后准确定位，动态行高测量后不持续跳动。
- 从生成中的最后一轮跳到历史 Query 后关闭自动跟随，尾部继续增长不拉回视口。
- 点击定位不改变思考面板状态、消息动画、会话 ID 或生成状态。
- 会话切换、新建空会话和消息加载后定位状态正确重置。
- 加入定位器后，500 条消息的 `.message-row` 挂载数量仍受 virtualizer 和 overscan 限制。

### Playwright 与回归

- 构造至少 12 个 Query 的长会话，断言五槽视窗最多显示五条完整横杠，且轨道仅额外保留上下缓冲项。
- 在定位器上向下滚轮可看到后续 Query，向上滚轮可返回前序 Query。
- 悬停不同横杠时卡片显示对应单行问题和最多三行回答摘要。
- 点击不可见窗口中滚轮浏览到的 Query 后，正文定位到对应 user 消息并更新白色高亮。
- 正文滚动经过多轮时，高亮项和五项窗口同步更新。
- 深色、浅色和桌面视口下卡片不超出可视区域、不遮挡输入区。
- 窄屏视口不显示定位器，现有会话抽屉、正文滚动和输入功能不回归。
- 保留并通过现有虚拟列表快速滚动、动态高度、流式贴底、用户上滚暂停和回到底部测试。

## 验收标准

- 当前会话有 user 消息且桌面空间足够时，正文左侧显示 Query 定位横杠。
- 任意时刻最多显示五条横杠；超过五条时可在定位器上使用滚轮浏览全部 Query。
- 当前 Query 在定位器的中间槽位保持高亮；滚动时可从相应边缘看到代表前/后 Query 的横杠逐渐进入，静止后回到完整的五槽窗口。
- 当前正文轮次横杠为白色高亮并明显长于灰色普通横杠。
- 悬停或聚焦横杠时，卡片正确显示一行用户 Query 和最多三行灰色 assistant 正文。
- 点击或键盘激活任意横杠后，正文准确定位到对应 user 消息。
- 用户直接滚动正文时，当前高亮项与五项窗口及时同步，overscan 不造成提前切换。
- 跳转历史 Query 后，流式输出不会把用户强制拉回底部；原有底部跟随和“回到底部”行为不回归。
- 500 条混合消息时不为全部 Query 创建正文 DOM 锚点，消息挂载数量仍由虚拟范围决定。
- 深浅主题、桌面布局、键盘焦点和辅助技术语义可用；窄屏正文不被遮挡。
- lint、类型检查、全部 Vitest、Playwright 和生产构建通过。

## 已知限制与暂不包含

- 移动端或窄屏的替代 Query 导航入口；首期直接隐藏定位器。
- 在定位器中搜索、过滤、编辑、复制或展开完整 Query/正文。
- 用思考过程生成摘要，或在预览卡片中渲染完整 Markdown、代码高亮和图片。
- 在浏览器刷新或切换会话后恢复定位器手动浏览到的五项窗口。
- 为尚未加载到前端的历史消息提供导航；未来若引入消息分页，需要另行设计跨页索引和加载后定位。
- 改变消息 API、会话持久化、模型上下文或虚拟列表的分页策略。
