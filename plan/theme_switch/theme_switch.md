# 浅色与深色主题切换

## 目标

为 Web 端增加浅色与深色两种界面主题。首次访问以及没有有效本地偏好时始终使用浅色主题；用户主动切换后，将选择保存在浏览器本地，刷新或重新打开页面时继续使用上次选择。

主题切换只改变界面外观，不影响当前会话、消息、推理强度、生成状态或服务端数据。桌面端和移动端均需提供可访问的切换入口，并完整覆盖现有页面的主要表面、文本、边框、浮层和交互状态。

## 当前基线

- Web 端使用 Vue 3、Vite 和单份全局 `style.css`，主要颜色当前以浅色硬编码值存在。
- 应用顶栏已有运行状态、推理强度选择器和新对话按钮，尚无主题切换入口。
- `index.html` 中的 `theme-color` 固定为浅色，应用在 `main.ts` 中直接挂载。
- 代码高亮固定导入 `highlight.js` 的深色样式，其余聊天界面以浅色为主。
- 项目已经使用版本化 localStorage key 保存推理强度和当前会话，可沿用相同的容错与测试模式。
- 主题属于纯前端偏好，不需要修改共享契约、API、数据库或 Provider。

## 已确认范围

- 仅提供 `light` 和 `dark` 两种主题，不提供“跟随系统”模式。
- 默认值固定为 `light`；即使操作系统偏好深色，首次访问也仍显示浅色。
- 用户选择通过版本化 localStorage key 持久化，在同一浏览器配置中刷新和重新打开后恢复。
- 页面根节点使用 `data-theme` 表示当前主题，并同步原生 `color-scheme` 与浏览器 `theme-color`。
- 顶栏提供单一主题切换按钮；浅色时可切换到深色，深色时可切换回浅色。
- 主题覆盖桌面端与移动端现有界面，不改变布局结构和业务行为。
- 浏览器存储不可用、读取失败或值非法时安全回退到浅色，不能阻止应用启动。

## 主题模型与持久化

产品层类型定义为：

```ts
type Theme = "light" | "dark";
```

持久化约定：

- localStorage key 使用 `ai-chat.theme.v1`。
- 只接受精确值 `light` 和 `dark`，不对未知值做别名映射。
- key 不存在、值非法或读取抛错时返回 `light`。
- 用户切换后先更新内存和页面主题，再尝试写入 localStorage；写入失败时当前页面仍应完成切换。
- 主题偏好只保存在浏览器本地，不写入 SQLite，也不随会话切换。

## 启动与渲染时序

为避免深色偏好在刷新时短暂闪现浅色界面，主题必须在 Vue 挂载前恢复：

1. `index.html` 的 `<head>` 中使用最小启动脚本读取 `ai-chat.theme.v1`。
2. 启动脚本只接受 `light|dark`，异常或非法值直接使用 `light`。
3. 在首屏绘制前设置 `document.documentElement.dataset.theme`、`color-scheme` 和匹配主题的 `theme-color`。
4. Vue 主题状态模块使用相同规则初始化，并在挂载后保持 DOM、状态和存储一致。
5. 切换时同步更新 `<html data-theme>`、原生表单配色和地址栏/浏览器外壳颜色。

启动脚本与主题状态模块必须共享同一 key、合法值和默认值语义；测试需要防止两处规则发生漂移。

## 界面与交互

- 在顶栏控制区加入主题切换按钮，与推理强度选择器和新对话按钮保持一致的视觉层级。
- 当前为浅色时显示月亮图标并使用“切换到深色模式”作为可访问名称；当前为深色时显示太阳图标并使用“切换到浅色模式”。
- 按钮使用原生 `button`，支持鼠标、触摸、Tab 聚焦、Enter 和 Space，无需额外菜单或选择弹层。
- 使用清晰的 hover、focus-visible 和 active 状态；图标不能作为唯一的无障碍说明。
- 移动端保持按钮可见并压缩为图标尺寸，不造成顶栏换行或页面横向溢出。
- 切换不关闭侧栏、弹窗或菜单，不清空输入草稿，也不改变滚动跟随状态。

## 样式设计

- 在 `:root` 定义浅色语义变量，在 `:root[data-theme="dark"]` 覆盖同一组变量。
- 变量按页面背景、表面层级、浮层、主次文本、边框、强调色、危险色、焦点环、阴影和遮罩等语义划分。
- 将现有影响主题的硬编码颜色逐步替换为变量，避免在深色选择器下复制整套组件规则。
- 深色主题需覆盖应用背景、侧栏、顶栏、会话条目、消息、思考过程、输入区、错误提示、下拉菜单、模态框、空状态和返回底部按钮。
- Markdown 标题、链接、引用、行内代码、表格和代码块需要分别验证；代码高亮颜色应与当前主题保持足够对比度。
- 同步设置滚动条、占位文本、禁用状态、边框与阴影，避免残留突兀的浅色表面。
- 颜色过渡应简短，并继续遵守现有 `prefers-reduced-motion: reduce` 规则。
- 普通正文、控件文字、焦点指示和危险状态应保持清晰可辨，目标为满足常规 WCAG AA 对比度要求。

## 实现边界与文件

预计涉及：

- `apps/web/index.html`：首屏主题恢复和初始 `theme-color`。
- `apps/web/src/composables/use_theme.ts`：主题类型、读取、切换、持久化和 DOM 同步。
- `apps/web/src/components/ThemeToggle.vue`：顶栏切换控件。
- `apps/web/src/App.vue`：接入主题状态和切换控件。
- `apps/web/src/style.css`：语义变量、深色变量和响应式样式。
- 对应 Vitest 与 `e2e/chat.spec.ts`：状态、组件和刷新持久化测试。

不修改后端 API、数据库 Schema、共享消息契约或聊天流式协议。

## 实现顺序

1. 建立主题类型、版本化存储 key、合法值校验、默认浅色和 DOM 同步方法。
2. 在应用首屏绘制前恢复主题，并同步 `data-theme`、`color-scheme` 与 `theme-color`。
3. 实现可访问的 `ThemeToggle`，接入顶栏并完成移动端适配。
4. 将全局颜色整理为语义变量，先保持浅色视觉不变，再补齐深色变量。
5. 检查 Markdown、代码高亮、浮层、错误态、禁用态、焦点态和滚动条等容易遗漏的区域。
6. 补充 composable、组件和 Playwright 测试，执行桌面端与移动端人工视觉检查。
7. 运行 lint、类型检查、全部 Vitest、Playwright 和生产构建；内部验证完成后将状态更新为 `implemented_pending_acceptance`。

## 测试计划

### 主题状态

- localStorage 无记录时初始化为 `light`。
- 操作系统为深色偏好时，无本地记录仍初始化为 `light`。
- 保存值为 `light` 或 `dark` 时准确恢复。
- 未知值、空字符串和旧版非支持值回退到 `light`。
- localStorage 读取或写入抛错时应用仍可启动并在当前页面切换。
- 切换同步更新响应式状态、`data-theme`、`color-scheme`、`theme-color` 和持久化值。

### 切换组件

- 浅色状态显示切换到深色的图标与可访问名称，深色状态反向显示。
- 点击、Enter 和 Space 均能触发一次切换。
- 控件可通过 Tab 聚焦，并具有可见焦点状态。
- 移动尺寸下按钮保持可见且不产生横向溢出。

### Playwright 与回归

- 首次进入页面时 `<html>` 为 `data-theme="light"`。
- 切换到深色后关键表面使用深色主题，localStorage 写入 `dark`。
- 刷新后首屏和 Vue 挂载完成后都保持深色，不回跳浅色。
- 切换回浅色并刷新后继续保持浅色。
- 非法存储值不会导致页面脚本异常，并回退浅色。
- 两种主题下发送、停止、切换会话、打开菜单和模态框等现有流程不回归。
- 桌面端与 390px 移动视口均无横向溢出，输入区保持可见。

### 验证命令

- `pnpm lint`
- `pnpm typecheck`
- `pnpm test`
- `pnpm test:e2e`
- `pnpm build`

## 验收标准

- 首次访问默认显示浅色主题，不受操作系统主题影响。
- 用户可以从顶栏在浅色和深色之间双向切换，变化立即生效。
- 刷新或重新打开页面后准确恢复上次选择，深色刷新时无明显浅色闪烁。
- 非法或不可用的浏览器存储安全回退浅色，不影响聊天应用启动与使用。
- 两种主题完整覆盖当前主要界面、Markdown 内容、浮层和交互状态，没有不可读文本或突兀浅色块。
- 桌面端和移动端切换入口均可用、可聚焦、具有明确可访问名称且不破坏布局。
- 主题切换不改变会话、消息、输入草稿、推理强度和生成状态。
- lint、类型检查、全部 Vitest、Playwright 和生产构建通过。

## 暂不包含

- 跟随操作系统、自动按时间切换或更多自定义主题。
- 云端同步、跨浏览器或跨设备同步主题偏好。
- 按会话保存主题、用户自定义颜色或主题编辑器。
- 后端接口、数据库字段或账户级偏好设置。
- 多标签页之间通过 `storage` 事件实时同步；刷新后读取持久化值即可。
