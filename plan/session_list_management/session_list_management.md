# 会话列表管理

## 目标

将现有本地单用户、单会话聊天应用升级为本地多会话应用：界面左侧展示可持久化的历史会话列表，用户可以切换会话并继续对话，也可以重命名或经二次确认后删除会话；界面右上角提供“新对话”入口，在确保当前会话已经保存后回到空白起始页。

每个自动标题基于该会话最近一轮的用户提问与模型回答，由现有用户配置的 DeepSeek API 调用 `deepseek-v4-flash` 无思考模式生成，建议长度为 20～40 个字符、硬上限为 48 个 Unicode 字素，且服务端必须对模型结果做结构化解析、规范化和硬性截断，不能把不可控的模型原始输出直接回填到界面。

## 文档依据

方案以 2026-08-10 的 DeepSeek 官方文档为准：

- [Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)：`deepseek-v4-flash` 支持 `thinking: { "type": "disabled" }`、非流式响应、`max_tokens` 和 JSON Output。
- [Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)：DeepSeek V4 默认开启思考，标题请求必须显式关闭思考，不能依赖默认值。
- [JSON Output](https://api-docs.deepseek.com/guides/json_mode/)：启用 JSON Output 时，提示词仍需明确要求 JSON，并应防御空内容和被 `max_tokens` 截断的响应。

## 当前基线

- 数据库已经包含 `conversations` 和 `messages` 表，消息通过 `conversation_id` 关联，删除会话时可级联删除消息。
- Repository、聊天读取、上下文组装和新消息写入仍固定使用 `DEFAULT_CONVERSATION_ID = "default"`，尚不能操作多个会话。
- 前端 `useChat` 只维护一个 `messages` 数组，加载接口固定为 `GET /api/chat`，发送接口没有会话 ID。
- 当前聊天消息在创建 turn、完成、停止和错误时已经写入本地 SQLite，不需要再引入浏览器数据库。
- 顶部栏已有品牌、运行状态和推理强度选择器，尚无“新对话”按钮。
- 当前页面采用单列布局，没有历史会话侧栏、会话操作菜单和模态框基础组件。
- API Key 只存在于 Fastify 服务端，DeepSeek Provider 已具有请求、超时、取消和安全错误映射能力。

## 已确认范围

- SQLite 是会话和消息的唯一事实来源；浏览器只保存界面偏好和最后选中的会话 ID。
- 消息继续按轮实时持久化，而不是等到点击“新对话”时才首次保存，避免关闭页面或进程异常时丢失内容。
- 历史列表按最后一条消息的活动时间倒序排列；重命名和自动标题回填不改变会话顺序。
- 自动标题在每个可用回答结束后基于最新一轮问答生成，因此能反映最近一条消息。
- 用户手动重命名后，标题来源切换为 `manual`；后续自动摘要不能覆盖手动标题。
- 自动标题与手动标题使用不同长度限制：自动标题硬上限 48 个 Unicode 字素；手动标题暂定硬上限 60 个 Unicode 字素。
- 当前版本保持全局单生成任务；生成过程中禁用会话切换、新建和删除，用户可以先停止生成。
- 新对话采用延迟创建：点击按钮只进入空白起始状态，用户发送第一条消息时才在服务器事务中创建会话，避免空会话堆积。
- 桌面端使用固定左侧栏；移动端使用可开合抽屉，避免压缩主聊天区域。

## 会话生命周期

### 应用启动

1. 并行读取会话列表和模型健康信息。
2. 从版本化 localStorage key 中读取最后选中的会话 ID。
3. 如果该 ID 仍存在，则加载对应会话；否则加载最近会话。
4. 如果数据库没有非空会话，则显示当前起始页，不预建空会话。

### 首次发送

1. 前端在没有活动会话 ID 时发送消息。
2. 服务端在一个 SQLite 事务中创建会话、用户消息和流式 assistant 消息。
3. SSE `meta` 返回服务端生成的 `conversationId`、消息 ID 和 turn ID。
4. 前端回填活动会话 ID，并把临时会话条目加入左侧列表。

### 继续对话

1. 前端发送当前 `conversationId`。
2. 服务端只读取该会话的模型历史，并把新 turn 追加到该会话。
3. 回答完成后更新该会话的活动时间和列表顺序。
4. 前端异步请求生成该轮自动标题；标题失败不能影响回答完成或下一轮发送。

### 新对话

1. 生成期间禁用按钮；用户可先停止当前生成。
2. 确认当前界面中的消息均已由服务端持久化，并刷新左侧列表中的当前条目。
3. 清空活动会话 ID、消息、输入草稿、错误提示和滚动状态。
4. 保留推理强度等用户偏好，显示现有起始页。
5. 在用户发送第一条新消息前不写入空会话记录。

### 删除

1. 第一次点击“删除”只把当前菜单切换为确认状态。
2. 用户再次点击“确认删除”后才调用删除接口。
3. 删除会话时依靠 SQLite 外键级联删除全部消息。
4. 如果删除的是当前会话，则加载列表中的下一条最近会话；没有剩余项时回到起始页。
5. 如果删除期间存在标题请求，服务端的条件更新必须安全地变成无操作。

## 数据模型与迁移

在现有 `conversations` 表增加：

- `title_source`：非空文本，枚举为 `auto | manual`，旧记录迁移后默认 `auto`。
- `title_turn_id`：可空文本，记录自动标题所依据的最近 turn，用于幂等和竞态保护。
- `updated_at` 普通索引：支持按最近消息活动时间读取会话列表。

字段语义：

- `title` 保存当前最终展示标题；不能保存未经校验的上游原始结果。
- `updated_at` 继续表示最近消息活动时间；重命名和标题生成不更新该字段，以免条目意外置顶。
- `title_source = manual` 时，任何自动标题请求只能返回当前标题，不能调用上游或写库覆盖。
- `title_turn_id` 等于请求 turn 时，接口直接返回现有结果，不重复消耗 DeepSeek API。
- 现有 `default` 会话和消息全部保留；如果它没有消息，则不出现在历史列表中。

Repository 拆分并新增以下能力：

- `listConversations()`：只返回非空会话，按活动时间倒序。
- `getConversation(id)`：返回会话元数据与按 position 排序的消息。
- `beginTurn(conversationId | null, ...)`：向现有会话追加 turn，或原子创建新会话及首轮消息。
- `getModelHistory(conversationId)`：严格按会话隔离上下文。
- `getLatestTitleTurn(conversationId)`：取得最近用户消息和对应 assistant 消息。
- `applyAutomaticTitle(...)`：在会话仍为自动标题且目标 turn 仍为最新时条件更新。
- `renameConversation(...)`：保存手动标题并切换标题来源。
- `deleteConversation(id)`：删除会话，依赖外键级联清理消息。

## 共享类型与校验

共享包新增：

- `ConversationSummary` 和 `ConversationListResponse`。
- `conversationId`、会话重命名和自动标题请求 Schema。
- `MAX_AUTOMATIC_TITLE_LENGTH = 48`。
- `MAX_MANUAL_TITLE_LENGTH = 60`。
- Unicode 字素计数和截断规则，确保前后端对中文、Emoji 和组合字符使用一致语义。
- `sendMessageRequestSchema` 增加可选或可空的 `conversationId`。
- `StreamMetaData` 增加服务端确认的 `conversationId`。

校验规则：

- 会话 ID 必须为非空、受长度限制的字符串，同时兼容旧值 `default` 和新 UUID。
- 手动标题 trim 后不能为空，不能包含控制字符，最多 60 个 Unicode 字素。
- 自动标题由服务端生成，不接受客户端提交标题内容。
- 对不存在或已经删除的会话统一返回 HTTP 404。

## API 契约

### 会话列表

`GET /api/conversations`

```json
{
  "conversations": [
    {
      "id": "conversation-id",
      "title": "SSE 与 SDK 对比",
      "titleSource": "auto",
      "createdAt": "2026-08-10T00:00:00.000Z",
      "updatedAt": "2026-08-10T00:05:00.000Z"
    }
  ]
}
```

列表不包含消息正文，避免初次加载把全部历史内容传给浏览器。

### 会话详情

`GET /api/conversations/:conversationId`

返回现有 `ChatResponse` 结构，即会话元数据和完整消息列表。

### 发送消息

`POST /api/chat/messages`

```json
{
  "conversationId": "conversation-id-or-null",
  "content": "用户问题",
  "reasoningLevel": "off"
}
```

- `conversationId` 为空时创建新会话。
- 非空时必须确认会话存在，再创建 turn。
- SSE `meta` 增加 `conversationId`，新旧会话使用相同前端处理流程。
- 生成历史必须使用该 conversation ID，不能再读取全局默认会话。

### 手动重命名

`PATCH /api/conversations/:conversationId`

```json
{
  "title": "我的自定义会话标题"
}
```

成功后返回更新后的会话摘要；写入时把 `title_source` 改为 `manual`，但不改变消息活动时间。

### 删除会话

`DELETE /api/conversations/:conversationId`

- 成功返回 HTTP 204。
- 会话不存在返回 HTTP 404。
- 生成中的当前会话由前端阻止删除，后端仍应拒绝删除存在活动生成的会话并返回 HTTP 409。

### 自动标题

`POST /api/conversations/:conversationId/auto-title`

```json
{
  "turnId": "latest-turn-id"
}
```

- 服务端根据 turn ID 从 SQLite 读取用户问题和 assistant 回答，不信任客户端提交消息正文。
- 只允许为当前最近可用 turn 生成标题。
- 同一 turn 重复请求直接返回当前标题。
- 手动标题直接返回当前标题，不调用 DeepSeek。
- 成功或本地兜底后返回更新后的会话摘要。

## DeepSeek 自动标题设计

### 请求

标题生成复用现有 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL` 和请求超时配置，通过 Provider 中独立的非流式方法发起：

```json
{
  "model": "deepseek-v4-flash",
  "messages": [
    {
      "role": "system",
      "content": "你是会话标题生成器。只输出合法 JSON 对象，且只能包含 title 字段。title 应准确概括最新问答，优先完整保留关键对象、领域和比较关系，建议为 20～40 个字符且最多 48 个字符，不得包含解释、Markdown、引号包装或换行。"
    },
    {
      "role": "user",
      "content": "包含 question 与 answer 的 JSON 文本"
    }
  ],
  "thinking": { "type": "disabled" },
  "stream": false,
  "response_format": { "type": "json_object" },
  "max_tokens": 96
}
```

使用 JSON Output 的目的不是把 JSON 发送给前端，而是将上游自由文本约束为单一字段。应用 API 最终只返回经过服务端校验的 `title` 字符串。

### 输入边界

- 输入只包含最近一轮的用户问题与模型最终回答，不发送整段会话历史。
- 对极长问答设置独立的服务端字符预算，优先保留问题全文和回答的开头/结尾，避免标题调用产生无界费用。
- 思考过程 `reasoning_content` 不参与标题生成。
- API Key、Authorization Header 和上游请求体不写入日志或客户端存储。

### 输出校验

1. 检查 HTTP 状态和响应结构。
2. 解析 `choices[0].message.content` 为 JSON。
3. 只读取字符串字段 `title`。
4. trim 并折叠连续空白，拒绝控制字符和换行。
5. 移除明显的 Markdown 标题符号或多余成对引号。
6. 使用 Unicode 字素规则硬截断至 48 个字符。
7. 如果结果为空、无法解析或上游失败，则使用用户问题规范化后的前 48 个字符作为确定性兜底。

自动标题少于 20 个字符可以接受，例如用户问题本身很短；48 个字符是不可突破的服务端上限。

### 触发与竞态

- assistant 状态为 `completed` 时触发自动标题。
- `stopped` 且已有可用回答正文时，可以基于部分回答生成标题。
- `error` 且没有回答正文时不额外调用 DeepSeek，直接使用用户问题兜底。
- 标题请求独立于聊天 SSE；回答完成后立即恢复聊天可用状态，不等待第二次模型调用。
- 写入标题前重新检查 `title_source`、最新 turn 和会话存在性，丢弃已经过时的结果。
- 标题失败只影响标题质量，不把聊天回答改成错误状态，也不阻塞“新对话”。

## 前端状态设计

新增 `useConversations` composable，负责：

- 会话列表、列表加载状态和错误状态。
- 当前会话 ID 及最后选中 ID 的版本化 localStorage 持久化。
- 加载、快速切换、新对话、重命名、删除和自动标题刷新。
- 使用 AbortController 或递增请求版本防止快速切换时旧详情覆盖新选择。
- 删除当前会话后的回退选择。

现有 `useChat` 调整为：

- 接收并暴露活动会话 ID。
- `loadChat(conversationId)` 按 ID 加载，不再固定读取默认会话。
- 乐观消息使用当前会话 ID；首轮暂时为空，并在 SSE `meta` 到达后回填。
- `sendMessage` 在请求体中发送活动会话 ID。
- 收到 terminal 事件并排空打字机后，请求该 turn 的自动标题。
- 切换会话前重置流状态、错误状态、打字机对象和滚动跟随状态。

## 界面与交互

### 页面布局

- 将根布局调整为左侧会话导航与右侧主聊天区域。
- 桌面侧栏使用稳定宽度，列表区域独立滚动，主聊天区域保留现有最大内容宽度。
- 当前条目使用清晰的选中背景；标题单行展示。
- 顶部栏右侧增加“新对话”按钮，与运行状态和推理强度选择器共同布局。
- 移动端通过菜单按钮打开覆盖式侧栏抽屉，选择会话后自动收起。

### 会话条目

- 普通状态只展示标题。
- 鼠标 hover、键盘 focus-within 或当前操作菜单打开时，右侧显示紧凑三点按钮。
- 标题容器使用 `min-width: 0`、单行和 `text-overflow: ellipsis`；完整标题通过 `title` 属性和无障碍名称提供。
- 三点按钮使用 `aria-haspopup="menu"` 和 `aria-expanded`。
- 点击条目主体加载详情；点击操作按钮不得同时触发会话切换。

### 操作菜单

- 菜单视觉参考用户提供的深色浮层示例，包含编辑图标、“重命名”、删除图标和“删除”。
- 支持点击外部、Escape 和选择操作后关闭，并把焦点返回触发按钮。
- 第一次点击“删除”后，菜单内部切换为红色“确认删除”和“取消”，不使用浏览器原生 confirm。
- 第二次点击“确认删除”才发送删除请求；请求期间禁用重复操作。

### 重命名组件

- 使用 Teleport 渲染到页面中央的模态框和遮罩层。
- 输入框预填完整标题并自动聚焦、选中文本。
- 支持 Enter 保存、Escape/取消按钮/遮罩关闭。
- 输入框 `maxlength` 与共享手动标题上限一致，显示剩余字符或当前计数。
- 空白标题不能提交；服务端错误保留输入并在组件内显示。
- 侧栏展示宽度与手动标题存储上限分离，超宽标题始终以省略号截断。

### 新对话按钮

- 生成期间禁用，并提供“请先停止当前回答”的可访问说明。
- 当前会话非空时，先确保它已出现在列表并触发尚未完成的标题刷新，再清空主区域。
- 当前已经是空白起始页时不创建新记录，只聚焦输入框。
- 清空消息、草稿、错误和滚动状态；不清除模型及推理强度偏好。

## 兼容性、安全与性能

- 迁移保留现有 `default` 会话和历史消息，无需用户手动处理数据库。
- SQLite 继续启用 foreign keys 和 WAL，删除会话由事务和级联约束保证一致性。
- 列表接口不返回消息正文，详情按需加载，避免会话数量增长后启动响应持续膨胀。
- 前端不能指定自动标题文本、模型名、system prompt 或 DeepSeek 请求参数。
- 手动标题必须按普通文本渲染，不能作为 HTML 或 Markdown 注入页面。
- 标题生成提示可能遭遇消息中的提示注入，最终安全边界是服务端 JSON 解析、字段白名单、字符规范化和硬长度限制，而不是只信任 system prompt。
- 全部 Provider 日志继续隐藏 Authorization；客户端接口永远不返回 API Key。
- 自动标题每个最新 turn 最多产生一次额外模型请求，失败不自动无限重试。
- 当前不实现跨会话并发生成或后台持续运行的回答任务。

- 重命名拒绝空白、控制字符和超过上限的标题。

### 数据库与 Repository

- 旧迁移数据库启动后保留默认会话和消息。
- 新会话首轮创建在同一事务中完成，不产生孤立空会话。
- 列表仅返回非空会话，并按最近消息活动时间倒序。
- 两个会话的 position、模型历史和消息读取完全隔离。
- 重命名保存手动来源，但不改变列表活动顺序。
- 删除会话级联删除消息，不影响其他会话。
- 自动标题对相同 turn 幂等；旧 turn、已删除会话和手动标题不能被覆盖。

### DeepSeek Provider

- 标题请求精确使用 `deepseek-v4-flash`、`thinking.disabled`、非流式和 JSON Output。
- 请求只包含最新问题和回答，不包含思考过程或其他会话历史。
- 正确解析单字段标题并规范化空白、引号和 Markdown 包装。
- 超长标题按 Unicode 字素截断至 48 个字符。
- 空 content、无效 JSON、缺失字段、HTTP 错误、超时和取消均进入安全兜底。
- 测试与日志不输出 API Key 或完整 Authorization Header。

### API

- 列表、详情、重命名和删除的成功、400、404、409 行为稳定。
- 没有 conversation ID 时创建新会话；存在时只追加到指定会话。
- SSE `meta` 返回准确的 conversation ID。
- Provider 收到的模型历史只来自当前会话。
- 自动标题接口从数据库读取问答，不接受伪造的客户端正文。
- 相同 turn 重复调用不会产生第二次 DeepSeek 请求。
- 标题生成失败不修改消息状态，也不影响继续发送。

### 前端组件与 composable

- 启动时恢复有效的最后会话；失效 ID 回退到最近会话。
- 快速切换时旧响应不能覆盖新选择。
- 首条消息收到 `meta` 后正确回填 conversation ID 和列表项。
- 新对话按先刷新列表、后清空主区域的顺序执行，且不产生空记录。
- hover、键盘焦点和触控场景都能打开条目菜单。
- 删除必须经过两次明确点击，取消和点击外部不会删除。
- 重命名模态框支持焦点管理、键盘操作、长度限制和错误保留。
- 长标题在侧栏截断，完整标题仍可访问。

### Playwright 与回归

- 创建第一个会话、生成自动标题、点击新对话并创建第二个会话。
- 在两个会话之间切换，分别继续对话，确认上下文不串线。
- 刷新浏览器后列表、标题、详情和最后选择仍存在。
- 重启本地服务后 SQLite 历史仍存在。
- 手动重命名后继续对话，标题不被自动摘要覆盖。
- 删除非当前和当前会话，验证二次确认及选择回退。
- 验证超长手动标题在桌面和移动视口均正确截断。
- 现有流式输出、停止、错误、推理过程折叠、自动滚动和移动端布局不回归。

### 真实 API 冒烟

- 完成一轮聊天后，确认额外标题请求为 `deepseek-v4-flash` 无思考模式。
- 标题只包含可回填文本，规范化后不超过 48 个 Unicode 字素。
- 标题生成失败或余额/速率错误时，聊天正文仍正常保存，并显示本地兜底标题。
- 确认 API Key、上游标题提示词和 Authorization Header 未进入客户端资产、接口响应或日志。

## 验收标准

- 左侧历史列表展示所有非空会话，并按最近消息时间倒序排列。
- 点击任一条目可加载完整原对话，并以正确的独立上下文继续发送。
- 每个未手动重命名的会话在最新回答完成后获得不超过 48 字的自动标题。
- 自动标题调用明确使用 `deepseek-v4-flash` 无思考模式，异常时有稳定本地兜底。
- 用户可以通过中央模态框重命名；手动标题与自动标题长度规则隔离，且不会被后续摘要覆盖。
- 超过侧栏可见宽度的标题单行截断并显示省略号，同时保留完整可访问文本。
- 会话删除必须经过条目菜单中的二次确认，确认后会话与消息永久从 SQLite 删除。
- 右上角“新对话”先确保当前会话已经进入历史列表，再回到空白起始页，且不会产生空会话。
- 刷新浏览器、重新打开页面和重启服务后，会话列表、标题与消息详情均保持存在。
- 生成期间的切换、新建和删除行为不会破坏正在写入的消息或显示错误会话。
- API Key 和上游鉴权始终只存在服务端。
- lint、类型检查、全部 Vitest、Playwright、生产构建和真实 API 冒烟测试通过。

## 暂不包含

- 用户账户、登录、云端同步或跨设备会话。
- 文件夹、标签、置顶、搜索、归档、批量删除或导入导出。
- 跨会话并发生成、切换后后台继续生成或多窗口同步。
- 用户自定义自动标题模型、提示词、长度或标题生成开关。
- 自动恢复为 AI 标题、手动触发重新摘要或标题版本历史。
- 将思考过程发送给标题模型。
- 会话分页或虚拟列表；首版先使用轻量摘要列表，达到规模阈值后再评估。
